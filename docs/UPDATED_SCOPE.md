This research proposes the development of an AI-powered Quality Engineering (QE) verification agent designed to help developers verify whether their implementation satisfies Jira story requirements before submitting the feature to the QA team. The solution aims to reduce the repeated feedback loop between developers and QA teams that commonly occurs when bugs are discovered during QA testing due to incomplete interpretation of acceptance criteria or missing validations in the implementation.

The proposed system integrates requirement analysis, automated test case generation, code verification, and structured reporting to provide developers with early feedback on the correctness of their implementation. The process begins by retrieving Jira story details and acceptance criteria, which serve as the primary input for the system. Based on these requirements, the system automatically generates structured test cases, including Behavior-Driven Development (BDD) feature files and test case scenarios that represent the expected system behavior defined in the story.

To enhance the quality and accuracy of generated test cases, the research proposes incorporating a fine-tuned domain-specific model specifically for the test case generation component. Test case generation is a well-bounded task with consistent inputs (Jira story descriptions and acceptance criteria) and structured outputs (BDD scenarios or unit tests), making it particularly suitable for supervised fine-tuning. A model trained on real story-to-test-case pairs can learn domain-specific patterns and produce more accurate and contextually relevant test cases compared to a general-purpose language model.

While the fine-tuned model is used for generating test cases, the verification component of the system relies on a general-purpose large language model. Verification requires analyzing implementation code across different programming languages, architectures, and business logic contexts. This task is inherently open-ended and requires strong reasoning capabilities rather than domain-specific pattern learning. As a result, a general-purpose LLM is better suited for evaluating whether the implementation logically satisfies the requirements described in the Jira story.

After generating the test cases, the system analyzes the implementation within a target GitHub repository using the reasoning capabilities of the LLM.

The system ultimately produces complementary verification output. Which is an LLM-based analysis report that evaluates whether the implementation logically satisfies the Jira story requirements. For scenarios where failures occur, the system provides implementation suggestions, enabling developers to review potential improvements and manually apply corrections before the feature is passed to QA.

From a system implementation perspective, the platform will utilize a Next.js-based frontend to provide an interactive interface where developers can submit Jira story references, review generated test cases, and access verification reports. The backend services will be implemented using Python, which will handle tasks such as interacting with AI models, retrieving repository data, executing verification processes. A PostgreSQL database will be used to manage structured data such as user inputs, story metadata, generated test cases, and verification results. Additionally, a storage bucket will be integrated into the system to store generated reports, test artifacts, and other files produced during the verification process. And also use a auth provider to handle user profiles and authentiaction

The system will also integrate with external development tools using GitHub APIs and Jira APIs, enabling automated retrieval of repository code, commits, and project metadata as well as Jira story descriptions and acceptance criteria. These integrations may be facilitated through Model Context Protocol (MCP) servers, allowing the AI components to securely interact with external services and retrieve the contextual information required for analysis and verification.

By combining requirement-driven test case generation, LLM-based code reasoning, and structured verification reporting, the proposed QE verification agent provides developers with a practical tool for validating their work early in the development process. This approach helps reduce the developer–QA feedback cycle while maintaining secure and controlled integration with existing software development workflows.

Additionally, the use of a fine-tuned model for test case generation introduces a clear research contribution. The effectiveness of the approach can be evaluated using measurable metrics such as test coverage, relevance to acceptance criteria, and correctness of generated test cases, enabling a systematic comparison between the fine-tuned model and a general LLM baseline.

In addition to the above components, the proposed system will incorporate a Retrieval-Augmented Generation (RAG) mechanism to improve the contextual understanding of the verification process. The RAG component will retrieve knowledge from multiple project knowledge sources such as Jira workspace data, Confluence documentation, and other project-related documentation repositories. These documents will be ingested and indexed within a vector database to enable efficient semantic retrieval of relevant information during verification.

When a Jira story verification is executed, the system will utilize the RAG pipeline to retrieve contextually relevant information related to the story. This may include related Jira stories, historical project discussions, Confluence documentation, architecture notes, implementation guidelines, and other relevant project artifacts. The retrieved contextual data will be supplied to the LLM along with the Jira story requirements and the GitHub repository implementation.

As part of the verification output, the system will provide generated test cases, the relevant GitHub repository links used during code analysis, and the RAG retrieval results including story-relevant project data, related Jira stories, and other contextual information identified from the project knowledge base. By incorporating RAG-based contextual retrieval, the system aims to improve the accuracy and completeness of verification by grounding the AI reasoning process in real project knowledge rather than relying solely on the Jira story description.
